## Ключевые технические риски

| # | Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|---|
| R1 | Валидность методики: баллы LLM не соответствуют суждению эксперта | высокая | высокое | двойная оценка, обязательные evidence, human review, calibration dashboard, отказ от автоматического кадрового решения |
| R2 | Нестабильный JSON от LLM | средняя | среднее | JSON Schema + Ajv + repair-retry + fallback в human review; тесты |
| R3 | Prompt injection из ответа кандидата | средняя | высокое | трёхчастная сборка промпта, экранирование, verifyEvidence (инъекция не создаёт цитату), детектор + техжурнал |
| R4 | Потеря кандидатской сессии при отказе LLM/сети | средняя | высокое | autosave на каждый ответ, статус PENDING, персистентная очередь, идемпотентные job-ы |
| R5 | Дороговизна LLM при массовом наборе | средняя | среднее | бюджеты, лимиты токенов, дешёвая модель для DEDUP, кэш идемпотентности |
| R6 | Утечка банка кейсов | средняя | высокое | эквивалентные варианты, рандомизация, одноразовые ссылки, отсутствие rubric в кандидатском API |
| R7 | Юридические риски (персональные данные) | низкая | высокое | минимизация полей, согласие, retention, экспорт/удаление, audit |
| R8 | Смещение оценки (bias) | средняя | высокое | отсутствие защищаемых характеристик в модели данных и промптах; калибровка; запрет непрофессиональных критериев |
| R9 | Дрейф модели LLM меняет исторические оценки | средняя | среднее | версионирование model/prompt/rubric, запрет молчаливого пересчёта |
| R10 | PDF-рендер (chromium) тяжёл для сервера | низкая | среднее | генерация в worker, очередь, кеш готового PDF в object storage |
| R11 | Кандидат «пишет правильные слова» без опыта | высокая | высокое | обязательные примеры из опыта, многоэтапные кейсы с раскрытием, проверка структуры рассуждения (§11), rule-flags на общие формулировки |
| R12 | Ошибочные веса/пороги администратора | средняя | среднее | валидация суммы весов, audit, версионирование, невозможность правки published-версии |

## Решения, принятые до кодирования

1. **Монолит Next.js + отдельный worker** (не отдельный API-сервис) — ADR-1.
2. **Route Handlers, не Server Actions** для мутаций — ADR-2 (документируемость и тестируемость).
3. **Session-based auth**, opaque токены, argon2id — ADR-4.
4. **Prisma** как ORM, миграции только вперёд — ADR-3.
5. **BullMQ + Redis** обязателен для оценки и PDF — ADR-5.
6. **Агрегация — в коде, не в LLM** — ADR-7.
7. **Свои SVG-графики** с обязательным табличным эквивалентом — ADR-8.
8. **PDF = печать web-отчёта headless Chromium** — ADR-9.
9. **Kelly-метрики не входят в Overall напрямую**, только в ось SELF_AWARENESS —
   SCORING §11 (методически осознанное решение, чтобы статистика решётки не
   превращалась в квалификационный балл).
10. **`NOT_ENOUGH_EVIDENCE` — отдельное значение**, перенормировка весов по
    покрытию, `coverage < 0.6` → «Недостаточно данных».
