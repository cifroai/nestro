# KELLY_METHOD — адаптация теста персональных конструктов Дж. Келли

## 1. Методическая позиция

Репертуарная решётка используется **как инструмент выявления профессиональных
критериев оценки, которыми кандидат реально пользуется**, а не как
personality-тест. Из методики берутся: элементы, триадический вызов
конструктов, ранжирование по биполярной шкале, laddering. Не берутся:
психологические типологии, нормативные шкалы личности, любые диагностические
интерпретации.

Выход методики — набор **персональных профессиональных конструктов** вида

```
предупреждает развитие осложнения ↔ начинает действовать после возникновения осложнения
```

и матрица оценок элементов по этим конструктам.

## 2. Элементы (§3)

Элементы задаются данными (`KellyElement`) и переопределяемы для каждой
должности. Базовый набор:

| Код | Формулировка (кандидату) | Флаги |
|---|---|---|
| E1 | Один из лучших инженеров, с которыми вы работали | — |
| E2 | Технически сильный специалист, регулярно нарушающий установленные процедуры | — |
| E3 | Дисциплинированный исполнитель: хорошо выполняет программу, слаб в нестандартных ситуациях | — |
| E4 | Инженер, способный заранее обнаружить предпосылки осложнения | — |
| E5 | Инженер, хорошо устраняющий уже возникшие осложнения | — |
| E6 | Инженер, способный аргументированно влиять на действия буровой бригады и смежных сервисов | — |
| E7 | Инженер, достигающий хорошего технического результата, но плохо документирующий решения | — |
| E8 | Инженер, которого вы не оставили бы самостоятельно на сложной скважине | — |
| E9 | Идеальный инженер соответствующей должности | `isIdeal` |
| E10 | Вы сами в настоящее время | `isSelf` |

**Фамилии реальных работников не запрашиваются.** Кандидату предлагается
мысленно закрепить за каждым элементом конкретного человека и записать
произвольную метку (например «А», «коллега с куста №3»). Поле метки
необязательно и не участвует в оценке.

## 3. Триады (§4)

Базовые комбинации: T1 `E1/E3/E8`, T2 `E2/E4/E9`, T3 `E1/E5/E6`,
T4 `E3/E4/E10`, T5 `E2/E6/E8`, T6 `E4/E5/E9`, T7 `E1/E7/E10`, T8 `E2/E3/E9`,
T9 `E5/E6/E10`, T10 `E3/E6/E8`.

Порядок триад частично рандомизируется: `randomizable = true` триады
перемешиваются детерминированным PRNG от `TestSession.randomSeed`
(воспроизводимость расследования инцидентов), первые две триады фиксированы
для стабильного «разогрева».

Каждая триада требует восемь ответов:

| # | Поле | Обяз. | Мин. длина |
|---|---|---|---|
| 1 | Какие два элемента наиболее похожи с точки зрения профессиональной эффективности | да | выбор пары |
| 2 | Чем именно они похожи | да | 40 |
| 3 | Чем третий отличается | да | 40 |
| 4 | Первый полюс критерия | да | 8 |
| 5 | Противоположный полюс | да | 8 |
| 6 | Почему этот критерий важен | да | 40 |
| 7 | Как проявляется непосредственно на буровой | да | 40 |
| 8 | Пример из собственного опыта | да | 80 |

**Анти-прайминг (§4):** до завершения формирования собственных конструктов
кандидату не показываются примеры готовых конструктов. В UI подсказки
ограничены грамматической формой («короткая фраза, 2–6 слов»), без
профессионального содержания. Проверяется e2e-тестом: страница триады не
содержит строк из справочника примеров.

## 4. Детекция дублирующих конструктов (§5)

После сохранения конструкта `K_new` вычисляется близость с каждым ранее
созданным `K_i`:

```
sim(K_new, K_i) = 0.6 · maxPoleSim + 0.4 · contextSim

maxPoleSim = max(
   cos(tokens(left_new),  tokens(left_i)),
   cos(tokens(right_new), tokens(right_i)),
   cos(tokens(left_new),  tokens(right_i)),   // инверсия полюсов
   cos(tokens(right_new), tokens(left_i))
)
contextSim = cos(tokens(importanceReason_new ⊕ rigManifestation_new),
                 tokens(importanceReason_i  ⊕ rigManifestation_i))
```

Токенизация: нижний регистр, удаление пунктуации, русский стеммер (лёгкий
суффиксный, `src/server/kelly/stemmer.ts`), стоп-слова. Векторизация —
TF без IDF (корпус мал), косинус.

Опционально (если LLM доступна) добавляется семантический шаг
`PromptTemplate(role = DEDUP)`, возвращающий `{ similar: boolean, score }`;
итоговый score = `max(лексический, семантический)`. Недоступность LLM не
блокирует прохождение.

Порог `similarityThreshold = 0.62` (настраивается). При превышении кандидату
задаётся строго нейтральный вопрос:

> «Эти критерии для вас означают одно и то же или являются разными?»

* ответ «разные» → обязательное поле «в чём различие», оба конструкта остаются;
* ответ «одно и то же» → новый конструкт помечается `isDuplicateOf`, кандидату
  предлагается переформулировать или перейти к следующей триаде.

**Автоматическое слияние запрещено** (§5) — код физически не содержит пути,
объединяющего конструкты без `candidateVerdict`.

Цель — 7–10 уникальных конструктов. Если после 10 триад уникальных < 7,
система предлагает дополнительные триады из резервного пула.

## 5. Репертуарная решётка (§6)

Матрица `конструкты × элементы (E1–E10)`, шкала 1–7:

| Значение | Подпись в UI |
|---|---|
| 1 | полностью соответствует левому полюсу |
| 2 | преимущественно левый полюс |
| 3 | скорее левый |
| 4 | промежуточное положение |
| 5 | скорее правый |
| 6 | преимущественно правый |
| 7 | полностью соответствует правому полюсу |

Требования UI: **оба текстовых полюса всегда видимы** над шкалой (левый —
слева, правый — справа); слова «плохой»/«хороший» отсутствуют; на мобильном —
по одному конструкту на экран с вертикальным списком элементов; прогресс
заполнения; автосохранение каждой клетки.

## 6. Laddering (§7)

Выбор конструктов для лестницы — детерминированный, по «значимости»:

```
significance(K) = 0.5 · discriminationPower(K)
                + 0.3 · selfIdealDistance(K)
                + 0.2 · candidateImportanceRank(K)

discriminationPower(K) = stdev(ratings across E1..E10) / 3      (нормировано)
selfIdealDistance(K)   = |rating(K,E10) − rating(K,E9)| / 6
```

Берутся top-3…top-5 (число — параметр версии, по умолчанию 4).

Процедура: вопрос «Почему для вас это важно?» → на основании ответа снова
«Почему это важно?». **Глубина строго 3–5 уровней**, счётчик жёстко ограничен
в движке (`MAX_LADDER_DEPTH = 5`); бесконечная рекурсия невозможна.

Останов раньше 3 уровней допускается, если кандидат дважды даёт ответ короче
30 символов — фиксируется как `terminatedEarly`, а не как ошибка.

Цель — восстановить профессиональную логику:
`показатель → действие → риск → результат строительства скважины`.
Достигнутый уровень цепочки классифицируется правилом (`ladderTerminalLevel`):
`METRIC` → `ACTION` → `RISK` → `WELL_OUTCOME`; достижение `WELL_OUTCOME`
питает ось `SELF_AWARENESS` и раздел отчёта.

## 7. Аналитика решётки (§21)

Пусть `G` — матрица `m конструктов × 10 элементов`, значения 1..7.

| Метрика | Формула | Назначение |
|---|---|---|
| Расстояние Я↔Идеал | `manhattan(G[:,E10], G[:,E9]) / (6m)` | нормированный разрыв 0..1 |
| Расстояние Я↔Лучший | `manhattan(G[:,E10], G[:,E1]) / (6m)` | — |
| Расстояние Я↔E8 | `manhattan(G[:,E10], G[:,E8]) / (6m)` | — |
| Евклидово расстояние | `sqrt(Σ(x−y)²)` | альтернативная метрика, выводится рядом |
| Сходство конструктов | Пирсон по строкам, с учётом инверсии (`max(r, −r)` c пометкой знака) | выявление близких критериев |
| Косинусное сходство | по центрированным строкам | устойчивость к сдвигу шкалы |
| Кластеры конструктов | агломеративная кластеризация, average linkage, `d = 1 − |r|`, отсечка 0.35 | группы критериев |
| Потенциальные дубли | пары с `|r| ≥ 0.8` **и** лексической близостью ≥ 0.5 | методическая проверка |
| Поляризация | доля оценок ∈ {1,7} | стиль заполнения |
| Распределение | гистограмма 1..7 по всей решётке | контроль качества |
| Противоречивость | доля пар (K_i, K_j) с `|r| ≥ 0.8`, но противоположной оценкой E9 | внутренняя несогласованность |

**Дисклеймер обязателен в отчёте и в API-ответе:** статистические расстояния
описывают структуру ответов кандидата и **не являются психологическим
диагнозом**; они не используются как самостоятельное основание кадрового
решения. Строка дисклеймера — часть контракта `GET /api/candidates/:id/report`
и проверяется тестом.

## 8. Хранение

```
CandidateConstruct   — конструкт + все 8 полей триады
ConstructRating      — клетка (constructId, elementId, rating 1..7)
LadderStep           — (constructId, depth, question, answer)
ConstructSimilarityCheck — (A, B, similarityScore, candidateVerdict, explanation)
GridAnalysis         — результат computeGridMetrics(), с engineVersion
```

`GridAnalysis.engineVersion` фиксирует версию математики: пересчёт метрик
старой сессии новой версией движка создаёт новую запись, а не переписывает
старую (§32).

## 9. Запрещённые формулировки

В UI, промптах, отчётах и коде запрещены: «личность», «тип личности»,
«психотип», «диагноз», «интроверт/экстраверт», «плохой/хороший специалист»,
«лжёт», «неискренен». Список — `src/lib/forbiddenVocabulary.ts`,
проверка — `tests/unit/forbiddenVocabulary.test.ts` (сканирует ru-строки
UI-словаря, шаблоны промптов и seed-данные).
