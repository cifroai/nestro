# Поручения — Telegram Mini App

Мини-приложение для отслеживания поручений по регламенту
«Структура и порядок поручений». Редакция для обкатки в Telegram.

Приложение — статичный веб-клиент (без сборки). Данные хранятся в
**Telegram CloudStorage** (синхронизация между устройствами одного пользователя),
с откатом на `localStorage` при запуске в обычном браузере.

> **Важно про эту редакцию.** Настоящая многопользовательская работа
> (исполнитель запросил перенос → контролёр согласовал со своего телефона,
> реальные push-напоминания) требует сервера — это следующий этап на VPS.
> Сейчас всё это можно **пройти на одном устройстве** через переключатель
> роли «Я:» в шапке: выберите исполнителя, запросите перенос; переключитесь
> на контролёра — согласуйте или верните. Логика и интерфейс настоящие,
> синхронизация пока локальная.

## Что можно протестировать

- **Три категории** с фиксированным порядком вывода: оперативные →
  организационно-технические → договорно-коммерческие.
- **Оперативные объекты** — штатный перечень из 12 позиций в неизменяемом
  порядке; объект всегда в сводке, даже без поручений
  (`Поручения отсутствуют.`). Новый объект вне перечня добавляется в конец
  с предупреждением «определить место» (Правило 4).
- **Исполнители** — индивидуально или **поровну** на двоих и более (отметьте
  нескольких участников).
- **Контролёр** — назначается на поручение.
- **Перенос срока** — исполнитель запрашивает новый срок с **обязательным
  пояснением**; контролёр **согласовывает** (срок применяется) или
  **возвращает** запрос с комментарием.
- **Вид отчёта об исполнении** — не требуется / текст / файл / фото / иное.
  Исполнитель сдаёт отчёт; **отчёт не закрывает** поручение (Отчёт ≠ закрытие).
- **Напоминания** — по каждому поручению настраивается интервал; поручения
  с приближающимся или истёкшим сроком собираются в разделе 🔔.
- **Сортировки** по регламенту: орг.-тех. (просрочка → срок → приоритет →
  без срока); договорные (группировка контрагент → договор → срок, финансовый
  риск первым).
- **Сводка** — строго по шаблону регламента, копируется одной кнопкой.
- **Команда** (⚙) — список участников, между которыми распределяются поручения.

## Структура проекта

```
index.html          — разметка и подключение SDK
css/styles.css      — оформление, тема от Telegram (--tg-theme-*)
js/model.js         — категории, объекты, правила, перенос/отчёты/напоминания
js/people.js        — участники команды и «действующее лицо» (тест ролей)
js/store.js         — хранение (CloudStorage / localStorage)
js/summary.js       — генерация сводки по шаблону
js/telegram.js      — интеграция с Telegram WebApp SDK
js/app.js           — состояние, рендеринг, формы, роли
.github/workflows/pages.yml — деплой на GitHub Pages
```

## Тест в Telegram (быстрый путь через GitHub Pages)

1. В репозитории: **Settings → Pages → Source → «GitHub Actions»** (один раз).
2. Workflow `Deploy Mini App to GitHub Pages` опубликует сайт при пуше в ветку.
   Итоговый URL виден во вкладке **Actions** / в **Settings → Pages**.
3. В [@BotFather](https://t.me/BotFather): выбрать бота → `Bot Settings →
   Web App` (или `/newapp`) → указать URL опубликованного приложения.
4. Открыть Mini App из меню бота.

## Локальный запуск (для разработки)

```bash
python3 -m http.server 8080   # затем открыть http://localhost:8080
```

Вне Telegram SDK недоступен — приложение работает на `localStorage`,
переключатель роли имитирует участников.

## Следующий этап (на VPS)

- Серверный бэкенд: общие поручения для всех участников в реальном времени.
- Реальная авторизация через Telegram (роль определяется по пользователю,
  тестовый переключатель убирается).
- Push-напоминания через бота о приближении срока и о запросах на перенос.
- Уведомления контролёру о новом запросе переноса; исполнителю — о решении.
- Хранение файлов отчётов на сервере.
- История изменений и архив закрытых поручений.
