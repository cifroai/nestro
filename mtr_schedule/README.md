# График закупки и доставки МТР для крепления скважин ЮГ-1, ЮГ-2, ЮГ-3

`build_mtr_schedule.py` генерирует книгу
`График_закупки_и_доставки_МТР_крепление_ЮГ-1_ЮГ-2_ЮГ-3.xlsx`.

Логистическая схема унаследована из исходного файла «График доставки цемента на скв. ГЕО-12»:
завод-изготовитель → ж/д до Владивостока → перевалка на судно → морской переход до
Петропавловска-Камчатского → доставка с базы Заказчика до скважины.

## Листы

| Лист | Назначение |
|---|---|
| Инструкция | Состав книги, логика расчета, легенда статусов, принятые допущения |
| Справочник | Единственное место ввода: длительности 8 этапов по 5 категориям МТР, программа крепления, номенклатура и объемы |
| ЮГ-1 / ЮГ-2 / ЮГ-3 | По каждой из 14 номенклатур: ед.изм., кол-во, дата потребности и сроки начала/окончания по каждому из 8 этапов |
| СВОДНЫЙ ГРАФИК | Диаграмма Ганта на 42 позиции (14 × 3 скважины), шкала 01.09.2026–30.06.2027 посуточно, вертикальная линия текущей даты |
| Сводная потребность | Суммарный объем закупки по номенклатуре, самая ранняя потребность, худший статус |

## Модель расчета

```
Дата потребности        = дата операции по креплению − 5 сут
Требуемая дата старта   = дата потребности − длительность цикла закупки и доставки
Дата начала (план/факт) = max(требуемая дата старта − 14 сут резерва; 20.09.2026)   <- поле ввода
Прогноз поставки        = дата начала + 8 этапов последовательно
Запас, сут              = дата потребности − прогноз поставки

Запас >= 14  -> В ГРАФИКЕ      (зеленый)
0 <= Запас < 14 -> РИСК        (желтый)
Запас < 0    -> СРЫВ ГРАФИКА   (красный)
```

Вертикальная линия текущей даты строится условным форматированием по `TODAY()` и
окрашивается в цвет статуса той строки, которую пересекает.
Файл пересчитывается при каждом открытии (`fullCalcOnLoad`), линия двигается сама.

## Проверка

`check.py` (вместе с `evalxl.py` — минимальный вычислитель формул Excel) вычисляет
каждую формулу книги и сверяет результат с независимо построенной моделью:
цепочки этапов без разрывов, соответствие прогноза сумме длительностей, статусы,
непрерывность шкалы времени, попадание всех интервалов в шкалу.

```
python3 build_mtr_schedule.py
python3 check.py
```

## Пересчет под другие данные

Все исходные данные — в верхней части `build_mtr_schedule.py`:
`OPERATIONS` (программа крепления), `NOMENCLATURE` (перечень и объемы),
`CATEGORIES` (длительности этапов), `TODAY` / `PROCUREMENT_READY` / `TARGET_BUFFER`.
В самой книге те же данные правятся на листе «Справочник» (желтые ячейки) —
без перегенерации.
