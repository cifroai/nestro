# Сводный график поставки МТР для крепления скважин ЮГ-1, ЮГ-2, ЮГ-3

Южный участок Мутновского месторождения.
`build_mtr_schedule.py` генерирует книгу
`График_поставки_МТР_крепление_ЮГ-1_ЮГ-2_ЮГ-3.xlsx`.

Логистическая схема унаследована из исходного файла «График доставки цемента на скв. ГЕО-12»:
завод-изготовитель → ж/д до Владивостока → перевалка на судно → морской переход до
Петропавловска-Камчатского → доставка с порта до скважины.

## Редакция 2

Приняты правки Заказчика в листе «Справочник»:

- переформулированы наименования 8 этапов поставки;
- заблаговременность доставки на скважину 5 → **10 сут**;
- номенклатура расширена с 14 до **16 позиций**: добавлены «Цементная смесь буферная
  (все колонны)» и «Труба фильтр-хвостовик ОК-168»;
- пересмотрены объемы, единицы измерения (т → тн) и обоснования по всем позициям;
- в графе ИТОГО учтен резерв «+1 шт на 3 скважины» по тех.оснастке ОК-426 и ОК-168,
  пакеру и переводнику;
- этап крепления «Хвостовик ОК-168» → «Фильтр-хвостовик ОК-168»;
- переводник 245/168 → «Разъединительный переводник СБТ-127/168 (левый/правый)».

Даты операций по креплению — по письму руководителя направления отдела бурения скважин
от 15.09.2026 (направление, кондуктор, эксплуатационная колонна по всем трем скважинам).
Срок спуска фильтр-хвостовика в письме не задан: принят +21 сут к эксплуатационной колонне —
интервал, заданный Заказчиком по ЮГ-1 (18.12.2026 → 08.01.2027).

## Листы

| Лист | Назначение |
|---|---|
| Инструкция | Состав книги, логика расчета, легенда статусов, источники данных, вопросы к Заказчику |
| Справочник | Единственное место ввода: длительности 8 этапов по 5 категориям МТР, программа крепления, номенклатура и объемы |
| ЮГ-1 / ЮГ-2 / ЮГ-3 | По каждой из 16 номенклатур: ед.изм., кол-во, дата потребности и сроки начала/окончания по каждому из 8 этапов |
| СВОДНЫЙ ГРАФИК | Диаграмма Ганта на 48 позиций, шкала посуточно, вертикальная линия текущей даты |
| Сводная потребность | Объем закупки по номенклатуре с резервом, самая ранняя потребность, худший статус |

## Модель расчета

```
Дата потребности        = дата операции по графику − 10 сут
Требуемая дата старта   = дата потребности − длительность цикла закупки и доставки
Дата начала (план/факт) = max(требуемая дата старта − 14 сут резерва; 20.09.2026)   <- поле ввода
Прогноз поставки        = дата начала + 8 этапов последовательно
Запас, сут              = дата потребности − прогноз поставки

Запас >= 14     -> В ГРАФИКЕ      (зеленый)
0 <= Запас < 14 -> РИСК           (желтый)
Запас < 0       -> СРЫВ ГРАФИКА   (красный)
```

Вертикальная линия текущей даты строится условным форматированием по `TODAY()` и
окрашивается в цвет статуса той строки, которую пересекает. Файл пересчитывается при
каждом открытии (`fullCalcOnLoad`), линия двигается сама.

## Нормализация вёрстки

Высота каждой строки считается по фактическому объему текста (`text_lines` /
`autofit`) с учетом ширины столбца, кегля и отступа, в том числе для объединенных
диапазонов — Excel не выполняет автоподбор высоты для объединенных ячеек, поэтому
высоты проставляются явно. Заданы поля страницы, печать с вписыванием по ширине и
закрепление шапки.

## Проверка

`check.py` (вместе с `evalxl.py` — минимальный вычислитель формул Excel) вычисляет
каждую формулу книги и сверяет результат с независимо построенной моделью:
стыковка этапов без разрывов, соответствие прогноза сумме длительностей, статусы,
даты операций из письма, резерв в ИТОГО, непрерывность шкалы времени, попадание всех
интервалов в шкалу и отсутствие обрезанного текста в ячейках.

```
python3 build_mtr_schedule.py
python3 check.py
```

## Пересчет под другие данные

Все исходные данные — в верхней части `build_mtr_schedule.py`: `OP_DATES` (программа
крепления), `NOMENCLATURE` (перечень, объемы, резерв), `CATEGORIES` (длительности
этапов), `TODAY` / `PROCUREMENT_READY` / `TARGET_BUFFER` / `NEED_LEAD`.
В самой книге те же данные правятся на листе «Справочник» (желтые ячейки) —
без перегенерации.
